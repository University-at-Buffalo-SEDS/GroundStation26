# Camera access and broadcast operation

`camera_publish` grants camera/microphone sharing independently of stream management. Existing accounts default to denied; grant **Share camera and microphone** in account settings. A publisher can start, stop and rename their own feed. Only stream managers (`stream_master` / `stream_admin`) and application administrators can view low-latency camera feeds, access recordings, rename other feeds or manage the programme. `voice_transmit` independently grants crew voice joining/listening/transmitting; stream management alone does not grant crew voice. Administrators inherit all grants. The server enforces these rules in addition to hiding unavailable tabs.

The camera page defaults to the rear lens where the browser exposes it. Open the viewfinder, select a lens and microphone, choose whether to include audio, enter a friendly name, then start sharing. Switching lenses preserves the publication and selected microphone. Zoom appears only when the browser exposes a usable camera zoom capability. Browser camera audio is carried with video; crew voice is separate. For a physical Pi sender, optionally set a stream's `audio_device` to an ALSA input (for example `plughw:1,0`); the sender copies hardware H.264 and encodes microphone audio to AAC. Omit the field for video-only capture.

The mobile menu opens across the available screen with page navigation and tools. Sign in remains accessible with the menu closed. Voice push-to-talk suppresses selection/callouts and releases on pointer cancellation or loss of focus. Supported browsers request a screen wake lock during visible playback or capture and reacquire it after returning to the page. OS background suspension and unsupported wake-lock APIs still apply.

The programme buffers internally, accounting for the source's keyframe/segment duration. Audience UI shows **Buffering** when necessary and does not display delay settings. Playback avoids repeated near-edge seeks that can freeze long-GOP sources. Stream Manager offers live tiles with grid, main-and-side and featured presets, ordering buttons and a main-camera width control. **Save camera layout** persists a revision-checked layout and fades programme cameras into place. Camera layouts also apply to programme replays.

Use **Clean OBS source** in Stream Manager as an OBS Browser Source URL. It serves the programme directly without dashboard exit, mute, volume or playback controls. The URL contains a scoped media capability; authorized active requests renew it, and permission revocation still applies. OBS manages its audio routing. Normal audience controls stay anchored outside the moving telemetry scene.

For remote encoding on a separate computer, see [Video Transcoder](../../video_transcoder/README.md). The station's returned-feed path only remuxes. Selecting a worker is optional; original feeds remain available when it disconnects.
