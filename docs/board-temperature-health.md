# Board and host temperature health

STM32 health reports include internal die temperature; this is not ambient temperature. Firmware samples at most one temperature/VREFINT pair every five seconds. Factory two-point calibration and the measured VREFINT ratio compensate for supply voltage. G491/H523 calibration uses 12-bit codes; U585 uses 14-bit codes. Integer conversion preserves signed centidegrees Celsius and rejects missing calibration, zero reference readings and results outside -40..150°C.

RF, Power, Gateway, Valve and FC use otherwise unused ADC1. Valve preserves the common ADC12 clock already configured for pressure ADC2. Actuator uses ADC1 injected channels only from the safety task while the regular DMA scan is idle: it never stops DMA, preempts a regular scan, changes its regular sequence, or recalibrates the safety ADC. DAQ samples through its existing ADC1 owner after the eight acquired channels, preserving acquisition channel order, diagnostics and timeouts. Internal health reads have a separate one-millisecond conversion timeout. No ADC4 concurrency, DAQ network-rate change or new SD acquisition row is introduced.

The existing BOARD_HEALTH UInt32[24] report remains version 1, 96 bytes and unreliable at its existing five-second interval. Word 1 low bits 0..7 keep their original meanings. Bit 8 marks temperature valid, bits 9..15 encode sample age rounded upward in 100ms units, and bits 16..31 encode signed int16 centidegrees Celsius. Valid reports contain a sample no older than six seconds. Old decoders ignore these previously unused flag bits; no network/application IDs or counter words change. Old firmware appears as temperature unavailable. Dashboard readings expire after 15 seconds including wire sample age, report age and client elapsed time. A missing temperature never changes board liveness, command authority, control guards or watchdog state.

GS and RRLS additionally sample Linux CPU/package sensors every five seconds using a blocking worker, never from the network or topology lock. Only CPU thermal-zone and known CPU hwmon sources are accepted; the hottest valid CPU sensor is displayed. Missing, invalid and unsupported sensors report unavailable. macOS currently has no supported unprivileged CPU-temperature API used by this implementation; no helper, external command or privilege request is installed or invoked. Host measurements are exposed in the local backend's existing network-health snapshot, not injected into the MCU simulation or the radio. Remote host temperature exchange between GS and RRLS is not added: it requires a separately qualified compatible LAN/capability transport.

Primary sensor references: [STM32G491 datasheet](https://www.st.com/resource/en/datasheet/stm32g491ke.pdf), [STM32H523 datasheet](https://www.st.com/resource/en/datasheet/stm32h523vc.pdf), [STM32U585 datasheet](https://www.st.com/resource/en/datasheet/dm00639779.pdf), and the corresponding vendored ST LL ADC headers. [STM32U575/U585 errata](https://www.st.com/content/st_com/en/technical-documents/es0499-stm32u575xx-and-stm32u585xx-device-errata-stmicroelectronics.html) also applies. Hardware calibration accuracy and timing require measurements on each populated board; native and link checks establish neither.
