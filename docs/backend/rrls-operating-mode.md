# Primary operating mode on RRLS

The primary Ground Station reports its compiled operating mode (`normal`, `hitl`, or `test_fire`). RRLS automatically follows that mode **as observer metadata**, persists the last confirmed value, and presents it across UI failover. This does not rebuild RRLS, enable a compiled-out feature, grant a permission, or enable a local mission sequencer. Existing RRLS live-operation restrictions and local interlocks remain authoritative.

`GET /api/station_mode` requires the existing ViewData permission. The auth-session and GSE status responses also include `operating_mode`. Fields include `effective_mode`, `local_build_mode`, `synchronized`, `persisted`, `local_capabilities_match`, `authority`, and `error`. Missing/legacy metadata remains unavailable. After restart or loss of the primary session, a persisted value remains visible as last known, not synchronized. The UI identifies the primary mode separately from the RRLS local build and local sequence diagnostics.

No new setup is needed for display synchronization. Without `GS_STATION_PAIRING_FILE`, version-2 display queries/replies use the already accepted, fresh primary HEALTH session and a random 128-bit RRLS challenge. They are 24/25 bytes. Replies must match both current session and unconsumed, unexpired challenge. This is unencrypted, non-authorizing mesh telemetry (`authority: mesh_session`), not cryptographic identity verification. It never establishes authenticated settings presence or changes control authorization. HEALTH remains nine payload bytes.

When pairing is configured, only version-1 signed mode envelopes are accepted (`authority: paired_signature`). They bind the configured installation, primary and observer identities, a fresh observer challenge, and a durable primary boot generation. Signature, peer-role, stale challenge and older/conflicting generation checks precede any update. An invalid pairing file or unsigned message cannot cause a downgrade to display telemetry. The configured shared installation signing key has the same trust boundary as the existing paired station workflow.

One pending mode envelope shares the existing SETTINGS outbox and aggregate 256-byte/second allowance with paired documents. Admission never evicts other radio work. A primary may enqueue a mode reply after its dedicated worker validates a query, even when direct mode has not produced RRLS READY traffic. Query and reply share one mode slot. This reply-only admission creates no general settings presence, authenticated peer, liveness renewal or control lease; paired documents retain their existing admission checks. A bounded worker processes at most the existing four inbox slots per 500ms tick; signature verification and atomic durable file replacement run outside radio locks in one awaited blocking task. Challenges retry at most every five seconds, refresh after 30 seconds and expire after 30 seconds. A confirmed observation expires after 90 seconds or immediately when its underlying session disconnects/changes. A reply does not authorize a command or renew mesh liveness.

`GS_STATION_MODE_FILE` optionally overrides the state path. Defaults are `data/station-mode-rrls-display.json` for unpaired RRLS, or `data/station-mode-<paired-station-id>.json` with pairing. Observer writes occur only when the observed mode or signed generation changes, not on freshness renewals. A failed write preserves the previous displayed value and pending challenge for retry. On the paired primary, its generation is incremented durably once per process startup.

Software verification uses synthetic keys/files, production Mesh envelope parsing and the actual Wasm UI with two isolated HTTP origins and signed existing discovery failover. It does not establish physical radio or device qualification. Browser sessions are independently authorized synthetic sessions on both origins; the test adds no cross-origin credential transfer mechanism.
